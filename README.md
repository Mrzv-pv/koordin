# Правовая помощь — Словения

Сайт практики юридической помощи для граждан России, живущих в Словении,
и открытая библиотека при ней.

Главная страница построена вокруг **онлайн-консультации**: предложение, талон
записи, как проходит встреча, что приложить к письму. Библиотека — второй
уровень: **59 вопросов** в 7 разделах, каждый факт со ссылкой на первоисточник
и датой проверки.

Логика такая: типовые вопросы разобраны открыто и бесплатно, а консультация
нужна там, где важны конкретные документы и сроки.

---

## Запуск

```bash
npm run dev
```

Соберёт сайт в `dist/` и поднимет сервер на <http://localhost:4321>.
Зависимостей нет — нужен только Node 18+.

```bash
npm run build     # только сборка в dist/
```

`dist/` — готовая статика: её можно залить на Vercel, Netlify, GitHub Pages
или любой обычный хостинг. Сборка кладёт туда `robots.txt`, `sitemap.xml`
и страницу `404.html`. А `vercel.json` (команда сборки, заголовки безопасности,
редиректы) лежит в корне репозитория: при деплое из Git Vercel читает его
только оттуда.

## Как это устроено

```
src/content.js         ← весь контент: разделы и вопросы. Правится только он
src/assets/styles.css  ← дизайн-система (токены, светлая и тёмная темы)
src/assets/site.js     ← поиск, темы, глубокие ссылки. Без зависимостей
src/assets/analytics.js ← баннер согласия и запуск GA4 после него
docs/content-plan.md   ← план развития библиотеки: что писать дальше
build.js              ← генерирует dist/ + карту сайта + разметку Schema.org
dist/                 ← результат сборки, в git не нужен
```

Шаблон шапки, подвала и `<head>` живёт **в одном месте** — в `layout()` внутри
`build.js`. Это главное отличие от предыдущей версии сайта, где эти блоки были
скопированы в каждый HTML-файл и успели разойтись между копиями: на одной
странице логотип вёл на главную, на другой нет; в одном подвале «Контакты»
вели на страницу, в другом — в никуда.

### Что делает сборка

- собирает 6 страниц из контента и общего шаблона;
- проставляет `<title>`, `description`, Open Graph, canonical на каждой странице;
- генерирует разметку `FAQPage` и `Organization` (Schema.org) — для справочника
  из вопросов и ответов это главный источник видимости в поиске;
- собирает `sitemap.xml` и `robots.txt`;
- **проверяет целостность**: дубли `id`, ссылки `related` в никуда, неизвестные
  категории. Ошибки печатаются в консоль при сборке.

## Как добавить или исправить вопрос

Всё в `src/content.js`, в массиве `entries`:

```js
{
  id: 'korotkiy-slug',          // попадает в URL: wiki.html#korotkiy-slug
  cat: 'health',                // id раздела из categories
  q: 'Вопрос так, как его задаёт человек',
  a: `Ответ. 60–160 слов, называйте конкретный орган и словенский термин.
Строки, начинающиеся с « • », отображаются как список.`,
  terms: ['ZZZS', 'napotnica'], // словенские слова с бланков — показываются чипами
  checked: '2026-09-18',        // дата сверки, видна читателю
  volatile: true,               // для сумм и ставок, которые меняются ежегодно
  sources: ['https://...'],     // первоисточники, ссылки под ответом
  caveat: 'Что нельзя обобщать', // отдельная плашка-предупреждение
  related: ['drugoy-slug'],     // перекрёстные ссылки, проверяются при сборке
  urgent: true,                 // только для раздела «Срочная помощь»
}
```

### Правила, которые стоит соблюдать

**`id` менять нельзя.** Он попадает в адрес страницы, и люди отправляют такие
ссылки друг другу. Изменённый `id` ломает чужие ссылки молча.

**Любое число — с датой.** Взносы, налоговые ставки, пороги и цены
пересматриваются раз в год. Пишите их вместе с датой, с которой они действуют,
и ставьте `volatile: true`.

**Не пишите то, чего не проверили.** Это справочник для людей, которые
принимают по нему решения о деньгах и статусе. Если факт не сверен с
первоисточником — либо не пишите его, либо опишите механизм без конкретной
цифры и поставьте `caveat`.

**`caveat` — не украшение.** Ставьте его там, где ответ зависит от конкретного
статуса человека: в миграционных и семейных вопросах обобщение вредит.

## Откуда взялся контент

Ответы не написаны по памяти: каждый факт сверялся с первоисточниками —
ZZZS, FURS, порталом e-uprava, текстами законов (ZTuj-2, ZDRS, ZBPP, ZPP, ZIZ,
SZ-1, ZVPot-1, ZDR-1) и европейским порталом e-justice. Ссылки на источники
выводятся под каждым ответом.

У ответа есть поле `confidence`. `verified` означает, что норма сверена с
первоисточником; `partly-verified` — что основная норма сверена, но часть
деталей зависит от практики конкретного учреждения. Читателю это видно:
такие ответы помечены как «Сверено частично». Умалчивать о неполной проверке
в справочнике, по которому люди принимают решения, нельзя.

`tools/import-research.js` — разовый скрипт, которым результаты сверки были
превращены в `src/content.js`. Он оставлен как документация происхождения
контента; повторно запускать его не нужно, дальше `content.js` правится руками.

## Технические решения и почему так

**В JSON-LD идёт не весь ответ.** Схема `FAQPage` дублирует текст ответа
для поисковых и ответных систем. На 134 записях полный дубль занимал треть
веса `wiki.html` (319 КБ из 956 КБ). Теперь в `acceptedAnswer` попадают
краткий ответ и пункты с потолком в 700 знаков, обрезанные по границе
предложения: фрагмент остаётся началом того же видимого текста, так что
разметка и страница по-прежнему совпадают. Константа — `ANSWER_MAX`
в `build.js`.

**Проверка ссылок ловит мягкие 404.** `tools/check-links.mjs` раньше ходил
`HEAD` и верил коду ответа. Так в справочнике жила ссылка на консульский
раздел, которая отдавала 200 и страницу «Страница не найдена». Теперь
проверялка читает тело, смотрит заголовок страницы на признаки «не найдено»
и отдельно ловит случай, когда ссылку на конкретную страницу молча уводят
на главную. Код ответа сам по себе ничего не доказывает.

**Ссылки только на первоисточники своей юрисдикции.** Консульские сайты
КД МИД устроены по одному шаблону, и в шести ответах оказались ссылки на
консульства в Торонто, Женеве, Осаке и Дублине — сайт посольства в Словении
в тот день не открывался. Формально страницы живые и текст похож, но
читателю в Любляне нужен его консульский отдел: порядок записи и условия
отличаются. Заменено на `slovenia.mid.ru/ru/consular_service/…`. По той же
причине британская копия регламента ЕС 2019/1111 заменена на EUR-Lex:
после Брексита это разные правовые акты.

**Отказ от аналитики удаляет куки, а не только флаг.** Google Analytics
ставит `_ga` на регистрируемый домен (`.koordin.eu`), а страница открыта на
`www.koordin.eu`. Код удалял куку с `domain=.` + `location.hostname`, то есть
с `.www.koordin.eu` — такого совпадения нет, браузер молча ничего не делает,
и куки со сроком жизни два года переживали отказ. Теперь перебираются текущий
хост и все его родительские домены. Если счётчик уже был запущен в этой
вкладке, страница перезагружается: выгрузить gtag на лету нельзя, а без
перезагрузки он поставил бы куки заново.

Там же: обработчик «Настроить аналитику» вешался через `querySelector`, то
есть только на первую такую ссылку. На странице о данных их две — в тексте и
в подвале, — и вторая молча никуда не вела.

**Число ответов в описании считается при сборке.** В `content.js` оно жило
строкой и обещало «59 ответов», когда их было уже 134, — причём именно эта
строка попадает в поисковую выдачу и в превью ссылки. Теперь в тексте стоит
`{N}`, а число и падеж подставляет сборка.

**Разметка организации стоит на каждой странице, перечень вопросов — только
в библиотеке.** Раньше весь JSON-LD был только на `wiki.html`, и главная —
та, куда в первую очередь приходит поиск, — не содержала ни одного узла.

**Сборка не пропускает ссылки на чужие консульства.** Ловушка повторилась
дважды: сайты КД МИД сделаны по одному шаблону, страница другого города
живая и текст похожий, поэтому глазами такая ссылка не цепляет. Но порядок
записи и местные требования у каждой миссии свои. Теперь `build.js` валит
сборку, если среди источников есть поддомен `kdmid.ru`, которого нет в
списке разрешённых (центральные сервисы юрисдикции не имеют и разрешены).
Заодно проверяется, что одна ссылка не стоит в ответе дважды.

Там же исправлено условие вывода «проверки пройдены»: оно перечисляло
проверки поимённо, новая в список не попала — сборка печатала ошибку и
следом «пройдено». Теперь сообщение об успехе привязано к счётчику
замечаний и коду выхода, так что следующая проверка учтётся сама.

**Порядок правил в `SOURCE_NAMES` важен.** Список перебирается сверху вниз
до первого совпадения, поэтому частные правила должны стоять перед общими:
дописанное в конец правило для `eur-lex.europa.eu` перекрывалось общим
`europa.eu`, и три разных источника схлопывались в один ярлык «Евросоюз».
То же было с `ess.gov.si` под общим `gov.si`. Официальный `pisrs.si` и
неофициальные сводки (`zakonodaja.com`, `racunovodstvo.net`) намеренно
разведены: у сводок текст отстаёт от действующей редакции, и один ярлык
на двоих вводил бы в заблуждение.

**Связи между ответами считаются с поправкой на частотность.** `related`
раньше не был заполнен ни у одной записи. Простой подсчёт общих слов лепил
пары по «договору» и «документу» — «признание диплома» оказывалось рядом
с «домашним насилием». Вес слова делится на частоту по всей библиотеке
(IDF), пары ниже порога 0.22 отбрасываются: 218 связей на 99 записей,
у остальных 35 близкого соседа просто нет. Пересчёт — скриптом, вручную
`related` можно править как угодно.


**Без Tailwind CDN.** Play-версия Tailwind — это 126 КБ JavaScript, который
компилирует стили в браузере у каждого посетителя, и сам Tailwind пишет в
консоль, что в продакшене её использовать не следует. Здесь обычный CSS
с переменными: около 12 КБ, без JS.

**Со сторонних CDN грузятся только шрифты.** Фотографии лежат локально
в `src/assets/img`, иконки — инлайновый SVG в `build.js`, фавиконка — data-URI.
Внешних ресурса два: шрифты Google Fonts (загружаются всегда, иначе страница
не отрисуется — это раскрыто на странице «Данные и cookies») и Google Analytics,
который **не загружается до согласия посетителя**. Если нужна полная изоляция
от Google, скачайте Alegreya и Alegreya Sans в `src/assets` и замените `<link>`
на `@font-face`.

**Аналитика включается только после согласия.** `src/assets/analytics.js`
хранит решение в `localStorage` (`koordin-consent`) и добавляет загрузчик
`gtag.js` в документ **лишь после нажатия «Принять»**. Пока ответа нет или он
отрицательный, ни одной куки Google не ставится и ни одного запроса на его
серверы не уходит. Consent Mode с параметром `denied` намеренно не используется:
он всё равно грузит `gtag.js`.

Обе кнопки баннера одинаковы по виду и размеру, «Отклонить» стоит первой.
Залитая «Принять» рядом с контурной «Отклонить» — это подталкивание, а
согласие, полученное подталкиванием, не считается свободным. Передумать можно
через ссылку «Настроить аналитику» в подвале, она же вызывает
`window.koordinConsent.open()`.

Счётчик GA4: `G-JLJNBJMGJ3` (ресурс koordin.eu, аккаунт Climatise EU,
часовой пояс Словения, валюта EUR). На `localhost` аналитика не запускается
никогда — `npm run dev` не должен попадать в статистику.

**Имена CSS и JS содержат хеш содержимого.** `styles.<hash>.css`,
`site.<hash>.js` — и поэтому им выставлен вечный `immutable`-кеш. Без хеша
это давало неприятный баг: после выкатки посетитель, заходивший в последний
час, получал новый HTML со старыми стилями, и вёрстка разъезжалась — при том
что локальная сборка выглядела правильно. Картинки без хеша, им оставлена
неделя; правило для `/assets/img/` в `vercel.json` идёт последним и перекрывает
общее.

**Инлайновые `style` в разметке запрещены.** Политика CSP на продакшене —
`style-src 'self'` без `unsafe-inline`, и браузер молча вырезает атрибуты
`style`. Ослаблять политику на сайте, который собирает юридические обращения,
неправильно, поэтому все такие места вынесены в классы, а сборка падает,
если инлайновый стиль появится снова.

**vercel.json не терпит посторонних ключей.** Комментарии вида `_comment`
роняют деплой с `schema validation failed` — формат строгий, пояснения живут
здесь.

**Контент в HTML, а не в JSON.** Поиск фильтрует уже отрисованный DOM. Поэтому
все 59 ответов видны поисковикам и читаются при отключённом JavaScript.

**`<details>` вместо самописного аккордеона.** Нативная семантика, работа с
клавиатуры и поиск по странице браузером — бесплатно и без ошибок с `aria`.

**Зум не заблокирован.** В `viewport` нет `user-scalable=no`: аудитория читает
с телефона плотный юридический текст, и запрет увеличения — это нарушение
WCAG 1.4.4 без всякой пользы взамен.

## Дизайн: что и почему

Направление — **приёмная практикующего юриста, а не лендинг сервиса**.
Отсюда конкретные решения:

### Цвет и перелив

Гамма синяя: от глубокой навигацкой сини `#17406f` через `#1f6aa8` и `#2f95c6`
к бирюзе `#4bbcd2`. Градиент на весь сайт **один** — переменная `--grad`
в `styles.css` — и применяется точечно: подложка первого экрана, акцентная
фраза заголовка, первичные кнопки, шапка талона, тонкие линейки над блоками.

Анимируются только два места: подложка героя (22 с) и акцентная фраза
заголовка (11 с). Кнопки переливаются не сами по себе, а при наведении —
сдвигом `background-position`. Всё остальное статично: если шевелится всё
сразу, перелив читается дёшево.

Анимации отключаются при `prefers-reduced-motion: reduce`.

### Картинки

Две фотографии из прежней версии сайта: бронзовая Фемида и белая модернистская
архитектура. Обе **скачаны и лежат локально** в `src/assets/img`, а не грузятся
с Unsplash и российского Tilda CDN, как раньше: страница не должна сообщать
о посетителе третьим лицам, и для аудитории этого сайта это не формальность.

Обе выведены в синий дуотон: подложка — фирменный градиент, фотография поверх
в режиме `mix-blend-mode: multiply` с обесцвечиванием. Режим выбран не случайно:
обе фотографии светлые, и при `luminosity` подложка осветлялась настолько,
что белый текст переставал читаться.

Размеры: герой 1400 px (152 КБ), полоса 1400 px (159 КБ), портрет для страницы
«О проекте» 800 px (54 КБ). Герой получает `fetchpriority="high"` и `preload`,
остальные — `loading="lazy"`.

- **Никаких карточек с тенями.** Разделы библиотеки на главной — типографский
  указатель с номерами, названиями, примерами тем и счётчиками. Это честная
  форма: перед вами действительно оглавление, а не витрина.
- **Талон записи вместо «блока с преимуществами».** Правая колонка первого
  экрана — панель с чернильной шапкой и строками «формат / язык / длительность»,
  как бланк записи на приём.
- **Линейки вместо коробок.** Границы и разделители несут структуру; тень
  не используется нигде.
- **Шрифты — суперсемейство Alegreya** (Alegreya + Alegreya Sans): гуманистическая
  антиква с хорошей кириллицей. Не Inter и не Golos — у сайта должен быть голос.
- **Палитра** — синяя гамма на прохладной бумаге `#eef2f8` с глубокими сине-чёрными
  чернилами. Красный отведён исключительно под сигнал срочности (112/113),
  охра — под пометки о неполной сверке.
