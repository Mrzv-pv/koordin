# Правовая помощь — Словения

Сайт практики юридической помощи для граждан России, живущих в Словении,
и открытая библиотека при ней.

Главная страница построена вокруг **онлайн-консультации**: предложение, талон
записи, как проходит встреча, что приложить к письму. Библиотека — второй
уровень: **59 вопросов** в 7 разделах, каждый факт со ссылкой на первоисточник
и датой проверки.

Логика такая: типовые вопросы разобраны открыто и бесплатно, а консультация
нужна там, где важны конкретные документы и сроки.

---

## Запуск

```bash
npm run dev
```

Соберёт сайт в `dist/` и поднимет сервер на <http://localhost:4321>.
Зависимостей нет — нужен только Node 18+.

```bash
npm run build     # только сборка в dist/
```

`dist/` — готовая статика: её можно залить на Vercel, Netlify, GitHub Pages
или любой обычный хостинг. Сборка кладёт туда же `vercel.json` с заголовками
безопасности, `robots.txt`, `sitemap.xml` и страницу `404.html`.

## Как это устроено

```
src/content.js        ← весь контент: разделы и вопросы. Правится только он
src/assets/styles.css ← дизайн-система (токены, светлая и тёмная темы)
src/assets/site.js    ← поиск, темы, глубокие ссылки. Без зависимостей
build.js              ← генерирует dist/ + карту сайта + разметку Schema.org
dist/                 ← результат сборки, в git не нужен
```

Шаблон шапки, подвала и `<head>` живёт **в одном месте** — в `layout()` внутри
`build.js`. Это главное отличие от предыдущей версии сайта, где эти блоки были
скопированы в каждый HTML-файл и успели разойтись между копиями: на одной
странице логотип вёл на главную, на другой нет; в одном подвале «Контакты»
вели на страницу, в другом — в никуда.

### Что делает сборка

- собирает 5 страниц из контента и общего шаблона;
- проставляет `<title>`, `description`, Open Graph, canonical на каждой странице;
- генерирует разметку `FAQPage` и `Organization` (Schema.org) — для справочника
  из вопросов и ответов это главный источник видимости в поиске;
- собирает `sitemap.xml` и `robots.txt`;
- **проверяет целостность**: дубли `id`, ссылки `related` в никуда, неизвестные
  категории. Ошибки печатаются в консоль при сборке.

## Как добавить или исправить вопрос

Всё в `src/content.js`, в массиве `entries`:

```js
{
  id: 'korotkiy-slug',          // попадает в URL: wiki.html#korotkiy-slug
  cat: 'health',                // id раздела из categories
  q: 'Вопрос так, как его задаёт человек',
  a: `Ответ. 60–160 слов, называйте конкретный орган и словенский термин.
Строки, начинающиеся с « • », отображаются как список.`,
  terms: ['ZZZS', 'napotnica'], // словенские слова с бланков — показываются чипами
  checked: '2026-09-18',        // дата сверки, видна читателю
  volatile: true,               // для сумм и ставок, которые меняются ежегодно
  sources: ['https://...'],     // первоисточники, ссылки под ответом
  caveat: 'Что нельзя обобщать', // отдельная плашка-предупреждение
  related: ['drugoy-slug'],     // перекрёстные ссылки, проверяются при сборке
  urgent: true,                 // только для раздела «Срочная помощь»
}
```

### Правила, которые стоит соблюдать

**`id` менять нельзя.** Он попадает в адрес страницы, и люди отправляют такие
ссылки друг другу. Изменённый `id` ломает чужие ссылки молча.

**Любое число — с датой.** Взносы, налоговые ставки, пороги и цены
пересматриваются раз в год. Пишите их вместе с датой, с которой они действуют,
и ставьте `volatile: true`.

**Не пишите то, чего не проверили.** Это справочник для людей, которые
принимают по нему решения о деньгах и статусе. Если факт не сверен с
первоисточником — либо не пишите его, либо опишите механизм без конкретной
цифры и поставьте `caveat`.

**`caveat` — не украшение.** Ставьте его там, где ответ зависит от конкретного
статуса человека: в миграционных и семейных вопросах обобщение вредит.

## Откуда взялся контент

Ответы не написаны по памяти: каждый факт сверялся с первоисточниками —
ZZZS, FURS, порталом e-uprava, текстами законов (ZTuj-2, ZDRS, ZBPP, ZPP, ZIZ,
SZ-1, ZVPot-1, ZDR-1) и европейским порталом e-justice. Ссылки на источники
выводятся под каждым ответом.

У ответа есть поле `confidence`. `verified` означает, что норма сверена с
первоисточником; `partly-verified` — что основная норма сверена, но часть
деталей зависит от практики конкретного учреждения. Читателю это видно:
такие ответы помечены как «Сверено частично». Умалчивать о неполной проверке
в справочнике, по которому люди принимают решения, нельзя.

`tools/import-research.js` — разовый скрипт, которым результаты сверки были
превращены в `src/content.js`. Он оставлен как документация происхождения
контента; повторно запускать его не нужно, дальше `content.js` правится руками.

## Технические решения и почему так

**Без Tailwind CDN.** Play-версия Tailwind — это 126 КБ JavaScript, который
компилирует стили в браузере у каждого посетителя, и сам Tailwind пишет в
консоль, что в продакшене её использовать не следует. Здесь обычный CSS
с переменными: около 12 КБ, без JS.

**Без внешних картинок.** Иконки — инлайновый SVG в `build.js`, фавиконка —
data-URI. Никаких запросов на сторонние CDN: страница не сообщает о посетителе
третьим лицам. Единственный внешний ресурс — шрифты Google Fonts; если нужна
полная изоляция, скачайте Golos Text и Literata в `src/assets` и замените
`<link>` на `@font-face`.

**Контент в HTML, а не в JSON.** Поиск фильтрует уже отрисованный DOM. Поэтому
все 59 ответов видны поисковикам и читаются при отключённом JavaScript.

**`<details>` вместо самописного аккордеона.** Нативная семантика, работа с
клавиатуры и поиск по странице браузером — бесплатно и без ошибок с `aria`.

**Зум не заблокирован.** В `viewport` нет `user-scalable=no`: аудитория читает
с телефона плотный юридический текст, и запрет увеличения — это нарушение
WCAG 1.4.4 без всякой пользы взамен.

## Дизайн: что и почему

Направление — **приёмная практикующего юриста, а не лендинг сервиса**.
Отсюда конкретные решения:

- **Никаких карточек с тенями.** Разделы библиотеки на главной — типографский
  указатель с номерами, названиями, примерами тем и счётчиками. Это честная
  форма: перед вами действительно оглавление, а не витрина.
- **Талон записи вместо «блока с преимуществами».** Правая колонка первого
  экрана — панель с чернильной шапкой и строками «формат / язык / длительность»,
  как бланк записи на приём.
- **Линейки вместо коробок.** Границы и разделители несут структуру; тень
  не используется нигде.
- **Шрифты — суперсемейство Alegreya** (Alegreya + Alegreya Sans): гуманистическая
  антиква с хорошей кириллицей. Не Inter и не Golos — у сайта должен быть голос.
- **Палитра** — бордо `#8c2f39` на тёплой серой бумаге `#f5f4f0` с сине-чёрными
  чернилами. Красный отведён исключительно под сигнал срочности (112/113),
  охра — под пометки о неполной сверке.
- **Иконки только там, где несут смысл** — поиск, закрыть, предупреждение.
  Заголовки разделов иконок не имеют.

Данные о консультации — формат, строки талона, шаги, списки «что вы получите»
и «что приложить к письму» — лежат в объекте `site.consultation` в
`src/content.js`. Длительность и стоимость там намеренно не проставлены:
их знаете только вы, а выдумывать цифры в юридическом сервисе нельзя.
